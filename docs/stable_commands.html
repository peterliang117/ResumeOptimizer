ResumeOptimizer Stable Commands

Local PowerShell commands for continuing the job-application workflow when Codex is unavailable or usage is exhausted. These commands call the existing repo scripts and keep the local Ollama/Qwen route active.

Quick Start

Set-Location C:\path\to\ResumeOptimizer
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\scripts\jobctl.ps1 status

Command Menu

Interactive Dashboard .\scripts\workflow_dashboard.ps1

Starts the local control UI at http://127.0.0.1:8770/.

Status .\scripts\jobctl.ps1 status

Shows batch status, next queued job, tracker counts, due follow-ups, and local LLM health.

Verify .\scripts\jobctl.ps1 verify

Runs doctor, tracker verification, and regenerates the tracker HTML report.

Run Current Batch .\scripts\jobctl.ps1 run-current-batch

Processes queued jobs using the local LLM route without discovering or refilling jobs.

Refill Next Batch .\scripts\jobctl.ps1 refill-next-batch

Generates a guarded refill review report after the current batch is exhausted.

Apply Reviewed Refill .\scripts\jobctl.ps1 refill-next-batch --apply-reviewed outputs\refill_candidates_YYYY-MM-DD-01.json

Adds 1 to 10 approved, hard-filtered, scored candidates to the queue under one batch ID.

Screen Refill Candidates .\scripts\jobctl.ps1 screen-refill-candidates outputs\refill_candidates_YYYY-MM-DD-01.json

Fetches job descriptions, scores candidates, and writes blocker/review flags back to the refill report.

Review Refill CSV .\scripts\jobctl.ps1 review-refill-report outputs\refill_candidates_YYYY-MM-DD-01.json --actionable-only

Exports the screened refill report to CSV so candidate, review, and fetch-failed rows can be inspected in a spreadsheet.

Prepare Next Packet .\scripts\jobctl.ps1 prepare-next-packet

Creates an application packet for the next queued job and stops at review.

Generate Handoff .\scripts\jobctl.ps1 generate-handoff --company "Example Co" --role "Senior Data Engineer"

Writes a browser or manual handoff JSON for one tracker row.

How The Pieces Fit

Codex optional PowerShell local Ollama Qwen Manual submit
1. PowerShell entry: jobctl.ps1 loads the local LLM environment and chooses the repo virtualenv Python.
2. Stable facade: jobctl.py maps short commands to the existing workflow scripts.
3. Workflow scripts: queue, tracker, application packet, resume tailoring, and verification stay inside the repo.
4. Local LLM: Ollama serves qwen3:8b for screening and qwen3:14b for resume/application work.
5. Human gate: final submit, legal attestations, privacy acknowledgements, and unsupported answers stay manual.

When Codex Usage Runs Out

  1. Open PowerShell on the machine that has the repo and Ollama.
  2. Run the quick-start commands above.
  3. Use status to decide whether there are queued jobs.
  4. Use run-current-batch only when the current batch still has queued jobs.
  5. Use refill-next-batch only when status shows refill_ready=yes and no queued jobs remain.
  6. Use screen-refill-candidates to automate JD fetching, scoring, and blocker detection for the generated report.
  7. Use review-refill-report --actionable-only to make a spreadsheet view of rows that still need attention.
  8. Review the generated refill report and approve 1 to 10 candidates before using --apply-reviewed.
  9. Use verify after state changes to regenerate outputs\application_tracker_summary.html.
Do not use these commands to bypass review. Model output is draft-only. Final submit, legal confirmations, and sensitive answers still require explicit human confirmation.

Safety Rules

  • run-current-batch starts with job_queue.py batch-status --target-size 10.
  • It does not discover replacement jobs or refill an exhausted batch.
  • refill-next-batch refuses to run unless the latest batch is exhausted and no queued jobs remain.
  • refill-next-batch writes a review report first and does not modify the queue by default.
  • --apply-reviewed accepts 1 to 10 candidates with approved=true, hard_filters_passed=true, and a valid match_score.
  • screen-refill-candidates does not set approved=true or hard_filters_passed=true.
  • review-refill-report exports CSV for review only; queue writes still use the JSON report.
  • Application answers come from profile\application_answers.json.
  • Profile truth comes from profile\facts.md.
  • generate-handoff blocks final submit, legal attestations, unsupported claims, and inferred sensitive answers.

Generated HTML Reports

To regenerate the live tracker summary HTML directly, run: 

.\.venv\Scripts\python.exe .\scripts\tracker_report.py

The output is written to outputs\application_tracker_summary.html.
